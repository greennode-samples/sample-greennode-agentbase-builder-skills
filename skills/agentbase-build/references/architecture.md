# Standard AgentBase agent architecture

## 1. Overview

```
 ┌───────────────┐  HTTPS + JWT    ┌─────────────────────────── AgentBase Runtime (container :8080) ─┐
 │ React Native  │ ──────────────▶ │ main.py  GreenNodeAgentBaseApp  POST /invocations  GET /health  │
 │ (src/frontend)│ ◀── JSON / SSE ─│   └─ app/service.py  (auth → tools → graph → trace)             │
 └───────────────┘                 │        ├─ app/auth/inbound.py   verify JWT (JWKS)               │
                                   │        ├─ app/tools/            local + memory + MCP tools      │
                                   │        ├─ app/graph/builder.py  LangGraph                       │
                                   │        └─ app/observability/    Langfuse v4                     │
                                   └──────┬──────────────┬───────────────┬──────────────┬────────────┘
                                          │              │               │              │
                              GreenNode MaaS LLM   AgentBase Memory   MCP Gateway        Langfuse
                              (tier + fallback)    (events+records)   (Connector+Policy) (traces, evals)
                                                                          │
                                                                    internal MCP servers / SaaS
   Other agents ◀──── A2A (/.well-known/agent-card.json, POST /a2a) ────▶ this agent  (optional)
```

## 2. Flow of 1 chat request

1. `main.py` receives `POST /invocations`; the SDK parses headers → `RequestContext(session_id, user_id, request_headers)`.
2. `service.handle()`:
   1. `authenticate()` verifies the JWT → `Principal(user_id=sub)`; overwrites `GreenNodeAgentBaseContext.user_id`.
   2. Validate the payload against the contract (`references/api-contract.md`).
   3. Open the Langfuse trace `agent.invoke` (user_id, session_id, tags, version).
   4. `collect_tools()` → local tools + memory tools + MCP tools (5-minute cache for non-per-user servers).
   5. `build_graph()` (cheap; built per request because tools may differ per user) with a shared checkpointer.
   6. Check whether a HITL interrupt is pending (chat ⇒ 409, resume ⇒ one is required).
   7. `graph.ainvoke` / `graph.astream` with `configurable = {thread_id: session_id, actor_id: user_id}`.
   8. Read `aget_state` → return `success` (response, tools_used) or `interrupted` (interrupt payload).
3. Graph:

```
START → compress → recall → [route] → agent ─┬─ no tool call ──▶ [reflect] ──▶ END
                                   ├─ HITL tool ─▶ approval (interrupt) ─▶ tools ─▶ agent
                                   └─ regular tool ────────────────────▶ tools ─▶ agent
```

## 3. Module responsibilities (what you may change)

| Module | Responsibility | For a new project |
|---|---|---|
| `main.py` | Create the app, lifespan (Langfuse init/flush), middleware (SSE, CORS) | Rarely changed |
| `app/config.py` | All env, validation (e.g. forbid `AUTH_MODE=none` outside local) | Add fields for new config |
| `app/service.py` | Payload contract, auth, root trace, invoke/stream, HITL resume | Add a new payload `type` if needed |
| `app/graph/builder.py` | The only graph | Add business nodes (router, sub-agent) |
| `app/graph/state.py` | State schema | Add business state fields |
| `app/llm/` | `get_llm(task)`: tiers reasoning/large/small, flow → tier table, fallback, adaptive routing | Pick a model per tier; add new flows to `DEFAULT_TASK_TIERS` |
| `app/a2a/` | A2A server + client | Enable when decision guide §5 is satisfied; write `A2A_SKILLS` |
| `app/memory/` | Checkpointer, LTM, compression | Tune strategy/namespace/thresholds |
| `app/tools/` | Registry + local tools + MCP loader | **Add business tools here** |
| `app/auth/` | JWT verification | Change IdP via env, code rarely changes |
| `app/identity.py` | Outbound credentials from AgentBase Identity | Decorate inner functions of tools (`/agentbase-build-identity`) |
| `app/hitl.py` | Approval node | Configure via `HITL_TOOLS` |
| `app/reflection.py` | Self-eval loop | Tune criteria via env |
| `app/observability/` | Langfuse v4 | Add project-specific PII masking |
| `app/prompts/system.md` | System prompt | **Write for the business domain** |
| `evals/` | Dataset + evaluators | **Write the dataset from the spec** |

## 4. Identity & session mapping

| Concept | Source | Used in |
|---|---|---|
| `user_id` | JWT `sub` (verified) | memory actor_id, Langfuse user, Identity USER_FEDERATION |
| `session_id` | Header `X-GreenNode-AgentBase-Session-Id` (frontend generates a UUID per conversation) | checkpointer thread_id, Langfuse session |
| `request_id` | Header or generated by the SDK | trace metadata, logs |
| `trace_id` | Langfuse | returned to the client for sending feedback |

## 5. Common extensions

- **Router / multi-agent within one agent:** `LLM_ADAPTIVE_ROUTING` provides a `route` node; for other business routers add a node using `get_llm("router")` + `with_structured_output`; sub-agents are subgraphs compiled **without** their own checkpointer (they share the parent graph's). An agent owned / deployed separately by another team ⇒ A2A.
- **RAG:** the retriever is a tool (`app/tools/`) or an MCP server; do not stuff documents into the system prompt.
- **Background / batch jobs:** call `service.run_chat()` in-process (skips inbound auth) — internal jobs only.
- **Multiple channels (Zalo/Telegram):** a channel is an adapter calling `/invocations`; if only a template chatbot is needed, consider OpenClaw (`/agentbase-deploy`).
